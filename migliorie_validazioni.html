Critica

Durata massima lezione — blocco e avviso graduato

LessonResource

Attualmente il sistema mostra solo ⚠️ La fine deve essere dopo l'inizio ma non impone nessun limite superiore alla durata. Una lezione da 100 ore viene salvata silenziosamente e distorce il conteggio ore del contratto.

⛔ Stato attuale
Nessun controllo sul valore massimo di durata. Una lezione con starts_at=09:00 e ends_at=09:00 del giorno dopo viene accettata.
✅ Proposta
Avviso (non bloccante) se durata > 4 ore. Errore bloccante se durata > 8 ore. Il messaggio cita la durata calcolata. 
// In LessonResource::formatDurationFromDates() — aggiungere dopo calcolo $mins
if ($mins > 480) { // > 8 ore
    return '🚫 Durata anomala: ' . static::formatDurationMinutes($mins) . ' — max consentito 8 ore.';
}
if ($mins > 240) { // > 4 ore
    return '⚠️ Durata insolita: ' . static::formatDurationMinutes($mins) . ' — verificare.';
}

// In LessonResource::form() sul campo ends_at — aggiungere regola:
DateTimePicker::make('ends_at')
    ->rules([
        function (Get $get) {
            return function (string $attr, $val, $fail) use ($get) {
                $mins = Carbon::parse($get('starts_at'))->diffInMinutes(Carbon::parse($val), false);
                if ($mins > 480) {
                    $fail('La lezione non può durare più di 8 ore.');
                }
            };
        }
    ])
Critica

Alert ore residue negative — lezione che sfora il contratto

LessonResource

Il placeholder "Ore rimanenti" mostra le ore residue ma non avvisa se la nuova lezione le porterebbe in negativo. L'operatore può creare una lezione che sfora il monte ore acquistato senza nessun feedback.

⛔ Stato attuale
Ore residue mostrate in sola lettura. Nessun avviso se la lezione in creazione supera il saldo.
✅ Proposta
Il placeholder diventa dinamico: calcola la durata della lezione corrente e segnala se il saldo scende sotto zero, con indicazione del deficit. 
// Sostituire il Placeholder 'hours_remaining' con versione live e reattiva
Placeholder::make('hours_remaining')
    ->label('Ore rimanenti (contratto)')
    ->live()
    ->content(function (Get $get, ?Lesson $record) {
        $c = $record?->contract ?? Contract::find($get('contract_id'));
        if (! $c) return '—';

        $remaining = (float) $c->hours_remaining;

        // Calcola durata della lezione in corso di modifica
        $mins = Carbon::parse($get('starts_at'))->diffInMinutes(Carbon::parse($get('ends_at')), false);
        $thisHours = max(0, round($mins / 60, 2));
        $afterSave = $remaining - $thisHours;

        if ($afterSave < 0) {
            return "🚨 Saldo residuo: {$remaining} h — questa lezione ({$thisHours} h) supererebbe il contratto di "
                 . abs($afterSave) . ' h';
        }
        if ($afterSave < 1) {
            return "⚠️ Residuo dopo lezione: {$afterSave} h (quasi esaurito)";
        }
        return "✅ Residuo dopo lezione: {$afterSave} h";
    })
Critica

Sovrapposizione docente — controllo mancante in fase di creazione manuale

LessonResource · LessonGeneratorService

Il LessonGeneratorService controlla le sovrapposizioni dello studente ma non quelle del docente. In più, il controllo è completamente assente nella creazione manuale da LessonResource. Un docente può quindi essere assegnato a due lezioni contemporanee.

⛔ Stato attuale
Nessun controllo docente in LessonResource. Il generatore controlla solo sovrapposizioni studente.
✅ Proposta
Validazione server-side su ends_at: se il docente ha già una lezione in quell'orario, mostrare errore con i dettagli del conflitto. 
// In LessonResource::form() — aggiungere rules() su ends_at o teacher_id
DateTimePicker::make('ends_at')
    ->rules([
        function (Get $get) use ($record) {
            return function (string $attr, $val, $fail) use ($get, $record) {
                $teacherId = $get('teacher_id');
                $startAt   = $get('starts_at');
                if (! $teacherId || ! $startAt || ! $val) return;

                $conflict = Lesson::query()
                    ->where('teacher_id', $teacherId)
                    ->whereNull('cancelled_at')
                    ->when($record?->id, fn($q) => $q->where('id', '!=', $record->id))
                    ->where('starts_at', '<', $val)
                    ->where('ends_at',   '>', $startAt)
                    ->first();

                if ($conflict) {
                    $fail('Il docente ha già una lezione in questo orario ('
                        . $conflict->starts_at->format('d/m H:i') . '–'
                        . $conflict->ends_at->format('H:i') . ').');
                }
            };
        }
    ])

Lezione nel passato — avviso esplicito

LessonResource

Creare una lezione con data nel passato è un'operazione lecita (inserimento retroattivo), ma avviene spesso per errore di battitura o copia-incolla. Un avviso non bloccante riduce questo rischio.

⛔ Stato attuale
Nessun avviso per lezioni nel passato.
✅ Proposta
Placeholder dinamico che avvisa se starts_at è nel passato: "📅 Attenzione: stai inserendo una lezione passata (ieri o prima)."
// Aggiungere Placeholder dopo starts_at
Placeholder::make('past_lesson_warning')
    ->label('')
    ->live()
    ->content(fn(Get $get) =>
        $get('starts_at') && Carbon::parse($get('starts_at'))->isPast()
            ? '📅 Attenzione: stai inserendo una lezione con data nel passato.'
            : null
    )

Lezione fuori dal periodo del contratto — avviso

LessonResource

Una lezione può essere pianificata per una data precedente all'inizio del contratto o successiva alla sua scadenza. Questo dato viene accettato senza feedback.

⛔ Stato attuale
Nessun controllo sull'intervallo di validità del contratto collegato.
✅ Proposta
Se starts_at è fuori dall'intervallo [contract.starts_at, contract.ends_at], mostrare avviso con le date del contratto.
// Nel Placeholder 'consumption_preview' o in uno nuovo, aggiungere:
$contractId = $get('contract_id');
$c          = $contractId ? Contract::find($contractId) : null;
$startAt    = $get('starts_at') ? Carbon::parse($get('starts_at')) : null;

if ($c && $startAt) {
    if ($c->ends_at && $startAt->gt(Carbon::parse($c->ends_at))) {
        return '⚠️ Data lezione successiva alla scadenza del contratto ('
             . Carbon::parse($c->ends_at)->format('d/m/Y') . ').';
    }
    if ($c->starts_at && $startAt->lt(Carbon::parse($c->starts_at))) {
        return '⚠️ Data lezione precedente all\'inizio del contratto ('
             . Carbon::parse($c->starts_at)->format('d/m/Y') . ').';
    }
}

2 · Gestione Contratti

Critica

Ore acquistate anomale — blocco inserimento valori assurdi

ContractResource · Step 2

Il campo hours_purchased accetta qualsiasi numero positivo. Non esiste un limite superiore: 500 ore, 9999 ore o un valore con virgola inserito per errore (es. 6,0 letto come 60) vengono salvati.

⛔ Stato attuale
Solo validazione numeric() e required(). Nessun limite massimo.
✅ Proposta
Avviso se > 200 ore, blocco se > 500 ore. Anche un avviso se il valore sembra troppo basso (es. < 1 ora per un corso non test).
// In ContractResource — campo hours_purchased:
TextInput::make('hours_purchased')
    ->numeric()->required()->default(0)
    ->minValue(0)
    ->maxValue(500)  // blocco hard
    ->hint(fn(Get $get) =>
        (float)$get('hours_purchased') > 200
            ? '⚠️ Valore insolito: verificare le ore inserite.'
            : null
    )
    ->hintColor('warning')
    ->rules(['max:500', 'min:0'])
Critica

Ore assegnate ai beneficiari ≠ ore totali — avviso visibile nel riepilogo

ContractResource · Step 4

Il placeholder assigned_hours_summary mostra il delta in formato testuale neutro. Se le ore assegnate non corrispondono al totale del contratto, il testo appare uguale — non c'è differenza visiva tra situazione ok e situazione anomala.

⛔ Stato attuale
"Ore contratto: 20 — Ore assegnate: 15 — Residuo: 5" — testo piatto, sempre uguale.
✅ Proposta
HTML con colore: verde se delta = 0, arancione se delta > 0 (ore non assegnate), rosso se delta < 0 (assegnate più del dovuto).
// Sostituire content() del Placeholder 'assigned_hours_summary':
->content(function (Get $get) {
    $totalAssigned = collect($get('beneficiaries') ?? [])
        ->sum(fn($r) => (float)($r['assigned_hours'] ?? 0));
    $purchased = (float)($get('hours_purchased') ?? 0);
    $delta     = round($purchased - $totalAssigned, 2);

    [$icon, $color, $msg] = match(true) {
        $delta == 0 => ['✅', 'green',  'Ore distribuite correttamente.'],
        $delta >  0 => ['⚠️', 'orange', "{$delta} ore del contratto non ancora assegnate."],
        default     => ['🚨', 'red',    'Assegnate ' . abs($delta) . ' ore in più del contratto!'],
    };
    return new HtmlString("<span style='color:{$color}'>{$icon} Contratto: {$purchased} h | Assegnate: {$totalAssigned} h — {$msg}</span>");
})

Validazione Codice Fiscale italiano — formato

ContractResource · StudentResource

I campi billing_tax_code e fiscal_code accettano qualsiasi stringa fino a 50/16 caratteri. Un CF malformato viene salvato senza avvisi.

⛔ Stato attuale
Solo maxLength(). Nessuna regex sul formato CF (16 caratteri alfanumerici, schema preciso).
✅ Proposta
Regex di validazione + normalizzazione UPPERCASE + avviso se la lunghezza non è 16 caratteri.
// Aggiungere a billing_tax_code e fiscal_code:
TextInput::make('fiscal_code')
    ->maxLength(16)
    ->formatStateUsing(fn($v) => strtoupper(trim($v ?? '')) ?: null)
    ->dehydrateStateUsing(fn($v) => $v ? strtoupper(trim($v)) : null)
    ->rule('nullable')
    ->rule('regex:/^[A-Z]{6}[0-9]{2}[A-Z][0-9]{2}[A-Z][0-9]{3}[A-Z]$/')
    ->validationMessages([
        'regex' => 'Il codice fiscale non sembra valido (formato atteso: RSSMRA80A01H501T).',
    ])

Validazione P.IVA — formato 11 cifre

ContractResource · CompanyResource

Il campo vat_number accetta qualsiasi stringa. Una P.IVA italiana ha esattamente 11 cifre numeriche. Errori di battitura (es. inserire il CF al posto della P.IVA) non vengono rilevati.

⛔ Stato attuale
Solo maxLength(50). Nessun controllo formato.
✅ Proposta
Regex + hint che mostra il formato atteso. Non bloccante per P.IVA estere.
TextInput::make('vat_number')
    ->maxLength(50)
    ->hint('Per P.IVA italiana: 11 cifre (es. 01234567890)')
    ->rule(function () {
        return function (string $attr, $val, $fail) {
            if (! $val) return;
            // Se sembra italiana (solo cifre) deve essere 11 caratteri
            if (ctype_digit($val) && strlen($val) !== 11) {
                $fail('La P.IVA italiana deve avere esattamente 11 cifre.');
            }
        };
    })

Alta

Conflitto slot stesso studente — stessa fascia oraria

ContractLessonSlot / Repeater beneficiari

È possibile aggiungere due slot per lo stesso studente con lo stesso giorno/ora. Il generatore salta i duplicati ma non avvisa mai l'operatore della configurazione incongruente.

⛔ Stato attuale
Due slot identici vengono salvati. Il generatore li gestisce silenziosamente.
✅ Proposta
Validazione univocità (student_id + weekly_day + weekly_time) a livello di Model booted o Filament rule.
// In ContractLessonSlot::booted() — aggiungere in saving():
static::saving(function (self $slot) {
    $exists = static::query()
        ->where('contract_id', $slot->contract_id)
        ->where('student_id',  $slot->student_id)
        ->where('weekly_day',  $slot->weekly_day)
        ->where('weekly_time', $slot->weekly_time)
        ->when($slot->exists, fn($q) => $q->where('id', '!=', $slot->id))
        ->exists();

    if ($exists) {
        throw new \RuntimeException(
            'Esiste già uno slot per questo studente in questo giorno/orario.'
        );
    }
});

Semaforo ore residue contratto — indicatore visivo nella lista

ContractResource · Tabella

Nella tabella contratti, le ore residue sono mostrate come testo. Non è immediato capire quali contratti stanno per esaurirsi.

Attuale
"Residue: 4.5" — testo piatto uguale per tutti.
✅ Proposta
Badge colorato: 🟢 > 20% ore residue · 🟡 < 20% · 🔴 < 2 ore · ⬛ esaurito.
// In ContractResource::table():
Tables\Columns\BadgeColumn::make('hours_remaining')
    ->label('Ore residue')
    ->formatStateUsing(fn($v) => number_format($v, 1) . ' h')
    ->color(function (Contract $r): string {
        $pct = $r->hours_purchased > 0 ? $r->hours_remaining / $r->hours_purchased : 0;
        return match(true) {
            $r->hours_remaining <= 0   => 'gray',
            $r->hours_remaining <= 2   => 'danger',
            $pct < 0.20                => 'warning',
            default                    => 'success',
        };
    })

Conferma prima di rigenerare lezioni — dialogo esplicito

ContractResource · Azioni

L'azione "Rigenera lezioni" cancella tutte le lezioni future non svolte. Non esiste un passaggio di conferma che mostri quante lezioni verranno eliminate.

Attuale
Click → rigenera immediatamente. L'operatore non vede quante lezioni verranno cancellate.
✅ Proposta
Modal di conferma con conteggio: "Questa azione cancellerà N lezioni future non svolte e ne genererà di nuove. Continuare?"
// Nell'azione di rigenerazione aggiungere ->requiresConfirmation() + ->modalDescription():
Action::make('rigenera_lezioni')
    ->requiresConfirmation()
    ->modalHeading('Rigenera lezioni')
    ->modalDescription(function (Contract $record) {
        $count = Lesson::where('contract_id', $record->id)
            ->whereNull('cancelled_at')

Ricerca studente per codice fiscale o telefono

StudentResource · Select beneficiario

La ricerca studente nel repeater beneficiari avviene solo per nome. Operatori che conoscono il CF o il numero di telefono dello studente non possono cercarlo con quei dati.

Attuale
Ricerca solo per first_name + last_name.
✅ Proposta
Estendere getSearchResults() per cercare anche su fiscal_code, email, phone.
// Nel Select 'student_id' del repeater beneficiari:
->getSearchResultsUsing(function (string $search) {
    return Student::query()
        ->where(function ($q) use ($search) {
            $q->whereRaw("CONCAT(first_name, ' ', last_name) LIKE ?", ["%{$search}%"])
              ->orWhere('fiscal_code', 'LIKE', "%{$search}%")
              ->orWhere('email',       'LIKE', "%{$search}%")
              ->orWhere('phone',       'LIKE', "%{$search}%");
        })
        ->limit(20)
        ->pluck(DB::raw("CONCAT(first_name, ' ', last_name)"), 'id');
})
UX

Contratti in scadenza — notifica proattiva nella dashboard

Dashboard / Widget

Non esiste un meccanismo che avvisi la segreteria dei contratti prossimi alla scadenza (es. entro 30 giorni) o con ore quasi esaurite (es. meno di 2 ore residue). L'utente deve cercarli manualmente.

Attuale
Nessun widget o notifica per contratti in scadenza o ore esaurite.
✅ Proposta
Widget Filament "Attenzione richiesta" con due elenchi: contratti in scadenza nei prossimi 30 giorni + contratti con < 2 ore residue.
// Creare app/Filament/Widgets/AlertsWidget.php:
class AlertsWidget extends BaseWidget
{
    protected function getViewData(): array {
        return [
            'expiring' => Contract::where('status', 'active')
                ->whereNotNull('ends_at')
                ->whereBetween('ends_at', [now(), now()->addDays(30)])
                ->with('students')->get(),

            'lowHours' => Contract::where('status', 'active')
                ->whereRaw('(hours_purchased - hours_consumed) < 2')
                ->whereRaw('hours_purchased > 0')
                ->with('students')->get(),
        ];
    }
}
